# 全范围适配与验收合同

本文件是后续实现应满足的检查清单，不表示这些业务测试已经执行。样例中的对象、收件人和记录均必须来自专用测试资源或用户明确指定的真实对象；本轮没有写飞书。

## 完整性

1. 官方 28 个入口和基线 27 个入口的模块有归属；四个会议旧名保留兼容映射，不能因上游合并而丢失旧业务流程。
2. 每个源 SKILL.md、references、scenes、scripts、assets 均有决定：保留并适配、合并但内容可定位、CLI 环境行为替换、或确实缺能力且明确说明。生成包必须提供源文件到产物的追踪表；不能用“低频”作删除原因。
3. 全部现有 503 个工具均可发现和调用；插件技能选择不会改变现有飞书权限，不因打包降低覆盖。
4. 每项缺口均有具体接口/传输/身份/宿主原因，不把同域工具数量当作完整支持证明。
5. 新旧两版指令冲突时按当前接口合同和用户已确认偏好统一；CLI 的宿主假设和强制模板不机械复制。

## 每个操作的迁移记录字段

`source_skill`、`source_file:line`、`source_command`、`intent`、`input_contract`、`mcp_tool_or_sequence`、`parameter_transform`、`output_transform`、`identity`、`scope_source`、`pagination`、`write_effect`、`idempotency`、`partial_failure`、`verification_level`、`remaining_gap`。

同 endpoint 的操作也要检查参数/响应；组合操作写明中间 ID 的传递和部分成功恢复点。没有 schema 时不得让模型猜参数。

## 全领域用例

| 模块 | 代表性请求 | 成功标准 / 缺口暴露标准 |
|---|---|---|
| shared | “现在连接的是谁？这个文档为什么没有权限？” | 显示当前连接身份；区分登录失效、缺 scope、资源 ACL、目录不支持；不循环重新登录 |
| doc | “只改这篇文档第三段的日期” | 正确找到块，保留其他段落/样式；引用过期时重读；不能新建代替编辑 |
| doc | “把这份长文完整总结” | 分页完整性可核对；并发修改时不把不同版本片段拼成同一全文 |
| drive | “把这两个文件移到给定文件夹，再导出其中一份 PDF” | 源/目标身份正确；移动和导出任务/文件下载分别记录完成情况 |
| wiki | “把这个知识库节点移到我的文档库” | 区分个人 Wiki library 与 Drive 根目录；底层对象和节点 token 不混用 |
| base | “把这个视图里所有待处理记录改为已完成” | 结构和筛选来自实际表；完整分页；只写目标字段和 ID；分批失败可恢复 |
| base | “创建含统计组件和自动化的应用模式页面” | 完成 BaseApp/组件/workflow 所需实际接口；缺具体接口时给出对应缺口，不能只建一个普通表交差 |
| sheets | “读 A1:F200，保留编号前导零，新增公式和图表” | 真正读取 values；typed 数据/公式/样式/图表分别验收；无读取能力时不输出假数据 |
| slides | “修改现有 PPT 第二页的标题和图片” | 页与块身份稳定；仅指定内容变化；图片上传和截图验证可追踪；不能用新 docx 替代 |
| markdown | “修改飞书里这个 .md 的两处文本” | 仍是同一原生 Markdown 文件；版本冲突和上传结果明确 |
| calendar | “把下周重复周会中的这一次改到周三” | 正确实例范围/时区；保留其他实例、参与人和会议室；不新建无关联会议 |
| contact | “找叫林夕的人，再展示候选” | 同名消歧；姓名搜索与已知 ID 查询边界明确；不能自选第一条进行副作用操作 |
| im | “向已确认的测试群发送这段内容” | 操作身份、群 ID、内容、消息 ID 和实际结果一致；超时先核查；不静默切 bot |
| mail | “给这封邮件起草回复，先不发送” | 真正保存草稿并保留原邮件线程；若无草稿 API，明确只完成对话草稿，不调用 send |
| task | “把这个任务完成，再重新打开，保留负责人和清单” | 修改同一任务；结果完整；未授权不加提醒或评论 |
| approval | “查看我的待审批，并通过指定的这一条” | query 范围、instance/task ID 和具体处理接口均正确；列表成功不冒充处理成功 |
| attendance | “查询我本月的打卡记录” | user 身份、月份范围、分页正确；不使用考勤排班/归档接口冒充个人打卡 |
| okr | “把这个 KR 的进度改到 75%，保留评分” | 指标/进展/score 不混淆；按 v2 合同更新，或明确当前仅 v1 能力 |
| whiteboard | “给现有画板补一条关系线” | 编辑原画板并保留其他节点；不能只读出节点或重建空板后声称完成 |
| apps | “在已有妙搭应用中修改页面并发布” | 复用正确 Spark 应用、代码和发布 ID；apaas/aily 查询不能代替开发发布 |
| event | “监听测试群的新消息，直到收到一条或超时” | 有 ready、事件和退出原因；注册订阅不等于收到事件；重连/丢失有状态 |
| meeting | “总结我昨天的全部会议，包含即时会议” | 时间范围/分页完整；不只查日历；Note、Minutes、Docx 产物分开；逐字稿缺失如实说明 |
| vc-agent | “让机器人进入指定测试会议，然后退出” | 明确 bot 身份及授权；入会、持续状态与离会均实际验证；不拿 user 控制 API 代替 |
| meeting-summary | “整理最近一周纪要，给来源链接” | 每场会有来源、读取状态、产物类型；不把权限失败解释成无纪要 |
| standup-report | “汇总明天的日程和未完成任务” | 时区、重复实例、未完成过滤和分页正确；只生成摘要，不创建任务 |
| explorer | “查一个日常入口没有的飞书能力” | 先发现 schema，再调用；目录外不能冒充任意 HTTP 代理 |
| skill-maker | “把刚才的飞书操作整理成可复用技能” | 生成实际 MCP 依赖与可用工具流程，引用完整；不夹带 CLI 安装或明文凭据 |

## 共同异常与宿主验收

- 直接意图、间接意图、错误触发、不完整输入、同名对象、无权限、空结果、部分来源失败、分页超过一页分别覆盖。
- 创建/追加/发送结果不明时不能盲目重试；恢复用返回 ID、幂等键或结果查询。
- 文件超限、异步任务未完成、缺少材料化接口时不谎报完成。
- ChatGPT 与 Codex 分别检查技能加载、依赖解析和工具名称映射；安装成功不等于使用成功。
- 修改技能后的新版本发布/重新扫描和新会话加载分别记录，不依赖云函数更新自动刷新已安装技能。
- 只执行与实际改动相关的测试；所有能力覆盖不是要求在一个生产账号上任意发送、删除或发布来探测。
