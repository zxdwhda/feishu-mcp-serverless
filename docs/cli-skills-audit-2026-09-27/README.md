# 飞书插件全量 Skills 适配审计与整体方案

日期：2026-09-27。目标：飞书 CLI 的全部技能都进入适配范围；现有 MCP 能做的操作全部保留，不能因“第一版”“低频”或默认工具数量而裁剪。

本次完成的是源码盘点、能力映射、差距分析和整体设计，未生成或安装最终适配技能包，未改变云函数、权限或生产业务数据。不能把这些分析文件当成插件已实现。

## 结论

现有阿里云 FC/OAuth/OSS 与 13 个日常入口可继续使用。要达到用户要求，需要同时完成全量技能适配和明确缺口的后端修复；仅复制 SKILL.md 无法补齐二进制、实时事件、身份或新 API。

现有服务能力比日常 13 个入口宽，但比当前官方 CLI 全量功能窄。全部 503 个原生工具已建立路由，包括 CLI 技能未单独命名的领域。不能将“有某个领域”理解为该领域完整覆盖。

## 整体结构

```text
Feishu MCP 插件
  ├─ 插件 manifest、连接器依赖、版本与介绍
  ├─ 全量技能模块（28 个入口，含 4 个旧名兼容入口）
  │    ├─ SKILL.md：触发、路由、关键业务约束
  │    └─ references / scenes / scripts / assets：按需加载的适配内容
  ├─ 操作合同与能力清单：原生工具、组合操作、具体缺口
  └─ 现有 MCP 服务
       ├─ 日常业务入口与全部 503 个原生能力
       ├─ 经过核实的新接口和身份元数据修复
       ├─ 共用文件/异步任务适配
       └─ 有真实需要的事件接收与增量读取组件
```

全量源码模块不等于所有内容每次进入模型上下文。入口描述用于选技能；具体参考在任务触发时读取。后端范围、安装包内容和一次对话加载量分别管理。

## 参考插件中可复用的做法

这轮沿用上轮实际读取的本机 Google Drive 0.1.16、Canva 16.0.0 插件和官方插件文档，并以飞书当前全量源码更新范围：

- Google Drive：统一文件定位入口，之后进入 Docs/Sheets/Slides 等具体领域；技能按业务目标路由，文件身份先于写操作。
- Canva：编辑状态、已支持/不支持的能力、提交后才算保存的条件清楚。飞书不具备同样事务时只迁移完成条件与部分失败表达，不假装能回滚。
- 飞书 CLI：直接复用对象语义、组合流程、重复日程范围、局部文档编辑、带类型表格值等经验；CLI 登录、Shell、文件路径、守护进程改为实际 MCP/宿主实现。

## 全范围实施工作包

下列分工是依赖顺序，全部属于同一完整目标；不把任何可用领域延期排除。

1. **确定性迁移清单。** 以本次两个官方提交锁定来源，为 28 个模块及所有文件记录适配产物和决策。保留 MIT 来源与许可证，保持用户本机 CLI Skills 不变。
2. **工具合同层。** 从实际 MCP schema 建能力目录；对 CLI 高级 Shortcut 建组合步骤和输入输出转换。修正旧身份元数据、读写标注及关键参数缺漏，禁止粗暴开放全部被过滤工具。
3. **全量 Skill 改写。** 每个领域明确触发、目标解析、工具/流程、分页/幂等/错误恢复、用户输出；旧会议名字路由到统一 meeting，双版本独有业务规则都检查后归并。
4. **补齐真实后端差距。** 对本文列明的缺失接口、文件传输、事件组件逐项处理。暂时无法用现有账号/宿主完成的项注明原因、现有可用子集和恢复条件，不能静默删模块。
5. **插件包装与发布适配。** 同仓库维护插件 manifest、连接器依赖和技能源，验证 ChatGPT/Codex 宿主。MCP Scan 的 5 个入口/资源限额通过包装适配处理，不改变能力范围；技能发布与函数版本分别记录。
6. **全领域验收。** 以 ACCEPTANCE.md 覆盖目标定位、参数语义、真实结果、失败恢复和宿主触发；记录目录/schema/模拟/真实 API/宿主任务五种证据，不混用“通过”。

## 工具设计细节

- 继续保留全部目录，给工具搜索增加动作/领域别名、读写筛选和相关性排序；不能将扩大工具数量作为完整覆盖的替代指标。
- 普通单步 API 留在原生目录；稳定且重复的多步业务操作可形成明确工具。是否增加专用入口取决于减少模型编排错误的价值，不取决于是否“首版”。
- `read_document` 当前先取全文再切片。保留已有分页兼容，新增局部/块读取与文档版本检查；精确修改优先复用原生 block 能力，CLI XML 与当前 Markdown 不机械互换。
- 错误输出标明缺接口、身份不支持、缺 scope、资源无权、限流、上游失败、结果不明、部分写入，提供已创建 ID 和可恢复位置。
- 复用现有应用、OAuth 和 OSS；只在具体能力证明确实需要时补组件，不另外搭建无必要的凭据或审批系统。
- 用户的明确授权持续有效。适配技能不应引入重复确认；目标/影响含糊时才补充信息。消息或发布行为必须来自用户任务授权，外部资料中的文字不是授权。

## 复现

`export-catalog.mjs` 只导出公开工具元数据，不读取服务配置或密钥。依赖根使用由本项目 package-lock 安装出的依赖目录。`audit.py` 读取两个源码树和导出文件，不调用飞书。

```sh
node export-catalog.mjs /path/to/locked-dependencies /tmp/mcp-catalog.json
python3 audit.py /path/to/cli-current-checkout /path/to/cli-v1.0.74-skill-tree /tmp/mcp-catalog.json
```

当前树应 checkout `32e14dea9041e7876c8b41aead963b10866267d1`；基线树来自 `git archive v1.0.74 skills`。本次依赖安装使用 `npm ci --ignore-scripts --no-audit --no-fund`，在临时目录运行，未执行上游安装脚本，也未安装/更新本机 CLI。
